## Resource clock and cleanup counting — precise proposal consistent with D151

Non-tail sum of 1,000,000 unique cells containing 1 must finish with 1,000,000; discarded million-list cleanup must finish without leaks or host-stack overflow. The resource watchdog is **not** an agent-effort cap.

Proposed clock starts immediately before each workload process launch and stops only after its workload-specific verification and all required cleanup complete. Include startup, source checking, fixture installation, begin/unused-input preparation, execution, streaming/snapshot readback and verification, terminal/failure observation, destroy twice, outside checks and host-fixture teardown. No pause/reset for observation, suspension or cleanup. Prior build/offline expectation preparation is outside this workload clock and inside the contributor effort ledger. This inclusive convention invents no setup/cleanup watchdog exemption.

Count all committed execution actions—including unused-input/entry/branch/return queued Give up holder/Free cell cleanup—in the same cumulative <=100,000,000 counter. Resume never resets it. Source/fixture setup and observer reads are not interpreter transitions. Post-terminal explicit destroy and host teardown have separate reported action/event counters, not artificial execution steps or additions to successful evaluation counts; they **still consume the same 600 seconds** and must reclaim without stack overflow/leaks. Exact counter/timestamp schema is proposed package detail, not a separately approved exception or unlimited cleanup allowance.

Large runs retain every physical cell operation and full states at start/every 10,000 execution transitions/suspend/fail/finish and before/after explicit cleanup operations, with all cleanup cell events retained. Do not dump the million-cell graph at every execution step. Small every-boundary coverage is unchanged. Record actual memory and effective 8 MiB stack, recheck available/cgroup resources before run. Timeout/stack overflow fails; passing supports only these bounded conditions and narrower large-run observation, not all-depth safety/speed/SLA.

## Exact sanitized interface artifact — declarations specify, they do not implement

BUILDER_BRIEF.md in the FINAL archive is the exact review artifact. It supplies grammar/requirements/public examples and complete proposed declaration/schema text. The key typed boundary is:

```rust
pub enum CheckFailure {
    Refused(Diagnostic),
    Failed { class: String, domain: Option<Resource> },
}
pub trait Candidate {
    type CheckedProgram;
    type Run;
    fn check_source(source: &[u8], allocations: &RuntimeCells)
        -> Result<Self::CheckedProgram, CheckFailure>;
    fn checked_dump(program: &Self::CheckedProgram) -> Vec<u8>;
    fn source_spans(program: &Self::CheckedProgram) -> Vec<u8>;
    fn begin(program: &Self::CheckedProgram,
             inputs: Vec<(String, Value)>, cells: RuntimeCells) -> Self::Run;
    fn advance(run: &mut Self::Run, budget: u64,
               committed: &mut dyn FnMut(&Self::Run, &[u8])) -> Outcome;
    fn snapshot(run: &Self::Run) -> Vec<u8>;
    fn public_output(run: &Self::Run) -> Vec<u8>;
    fn destroy(run: &mut Self::Run) -> Result<(), CleanupFailure>;
}
```

Invalid source is typed Refused; denied frontend numeric allocation is typed Failed/resource-exhausted/Number, **not a syntax Diagnostic**. Neither has a Run. Acceptance/host formats refused/class/span and pre-run failed/class/step="0"; it also formats invalid-fixture output. Candidate public_output handles only existing Run outcomes. No pre-run partial answer. Host process death is abnormal evidence, not fabricated recovery. Host pre-run formatter/check-failure adapter remains unfinished executable glue.

Callback gives commit metadata and incremental events/births; acceptance reads actual Observer and snapshots every tiny boundary or approved large checkpoint. No candidate expected state, fixture provenance, pointers, fault choices or private data. Acceptance assembles full traces. Begin is zero-step; initial execution cleanup is observable through advance. Snapshot is read-only; zero-budget and terminal reobservation do no work; prefixes/lifetimes continue across resume.

Minimal RuntimeCells surface is exactly allocate<T>(Resource, FnOnce()->T)->Result<T,Error>; read(u64)->Result<Cell,Error>; create(Cell)->Result<u64,Error>; write(u64,String,Option<u64>)->Result<(),Error>; detach(u64)->Result<Option<u64>,Error>; metadata(u64,u64,bool)->Result<(),Error>; free(u64)->Result<(),Error>. Cell fields: item:String, tail:Option<u64>, holders:u64, aside:bool. Error variants InjectedAllocationFailure/UnknownCell/InvalidDetach; Resource Number/Frame. RuntimeCells is opaque/nonconstructible by candidate; no Observer, fixture constructor, logs/pointers or failure controls. **Current whole cells crate is not this sanitized dependency.**

**Proposed exact Number-routing precision:** candidate-facing read yielding an owned numeric string executes inside Number allocation callback (allocate(Number, || read(id))), distinguishing gate denial from inner read errors. Candidate-owned strings supplied create/write come from gated parse/arithmetic/copy paths. Existing allocate drops its store borrow before callback, so this wrapper needs no read API repair. Acceptance Observer copies/host fixture bookkeeping are excluded. This does not intercept every host allocation or guarantee arbitrary OOM recovery. Existing failure fixtures were not retuned; they test generic preservation/ordinal classification, not actual whole-program numeric-attempt schedules. Candidate routing remains unverified.

The brief defines public JSON key order/status/value/span kinds, checked-node/path types, source span map, commit/snapshot metadata, typed run-wide births and separate failure/cleanup evidence. Failure abort records stay separate from the preserved committed-event prefix; cleanup events stay separate from evaluation counts. Current bridge supports only its smaller tested subset: extended site/result/abort/birth/span schemas and host formatting still require acceptance-owned executable validation.
